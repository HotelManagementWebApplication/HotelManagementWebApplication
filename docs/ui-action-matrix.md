# UI action matrix

Generated from the current executable frontend on 2026-09-19 after the
accepted P0/P1 and HR/Admin/Governance slices. The active boundary is
`frontend/src/App.tsx` and its imports (`app`, `features`, `shared/api`, and
matching tests). The legacy `frontend/src/pages` screens remain listed only
where the matrix says `legacy/unreachable`; they are not active routes.

## Reading rules

- `local` is navigation, form state, filtering, modal/detail selection, or
  route-parameter validation with no server request.
- `wired` means the active control calls the shared API caller and has a
  focused transport/session test, but the row does not have the complete
  focused outcome/refetch proof required for `verified`.
- `verified` requires a focused API/feature test plus observable pending/error
  handling and retry or successful query invalidation in the owning feature.
  For a business mutation, the evidence must also contain a concrete success
  or invariant-preserving rejection outcome; transport-only and source-only
  evidence never upgrades it to `verified`.
- `blocked` is an absent route, disabled unsupported control, or business
  mutation whose current evidence is only transport/source wiring or whose
  active branch is deliberately unavailable to the current actor. `mock` is
  reserved for an unreachable legacy screen; it is never evidence of a live
  business action.
- API cells use the actual method/path called by the current frontend. `—`
  means no request is emitted. Query names preserve the current controller
  contract, including backend camelCase binds such as `roomId` where they are
  still present.
- The shared client sends `Accept: application/json`, JSON `Content-Type` for
  bodies, `Authorization: Bearer <access_token>` when a token exists, and
  `Idempotency-Key` only when the caller supplies one. Error cells describe
  the current `ApiError` handling for 400/401/403/409/422/429.
- Roles are canonical employee roles from `shared/types/api.ts`; `anonymous`
  and `CUSTOMER` identify the public and customer identities. A `+ PERMISSION`
  suffix is the route/profile capability required by the current code.
- `/staff/hr` is owned by `HR`, `MANAGER`, `DIRECTOR`, and `ADMIN` with
  `EMPLOYEE_READ`; `/staff/admin` is owned by `MANAGER`, `DIRECTOR`, and
  `ADMIN` with `EMPLOYEE_READ`. HR has employee reads and shift permissions,
  but the backend grants no `EMPLOYEE_PROVISION` or
  `EMPLOYEE_PASSWORD_RESET`, so employee mutation controls remain blocked for
  an HR actor. Management-role mutation paths are listed only as wired where
  the current focused contract evidence supports the caller; this matrix does
  not claim live database or browser proof.
